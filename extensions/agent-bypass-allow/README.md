# Bypass auto-allow (Claude Code & Antigravity CLI)

Claude Code (`bypassPermissions`) and Google Antigravity CLI (`agy`, `toolPermission: "always-proceed"`) in bypass mode still stop on some calls, such as a read outside the working directories or a command with a dynamic target, and an unattended agent waits there. On the computers you choose, this extension installs a local hook (`PermissionRequest` for Claude Code, `PreToolUse` for `agy`) that allows those calls for Bash (`run_command`), the read-only tools (`Read`/`read_file`/`view_file`, `Glob`/`find_by_name`, `Grep`/`grep_search`, `LS`/`list_dir`, `NotebookRead`) and subagents (`Agent`/`invoke_subagent`), only in bypass sessions. Commands that delete or overwrite data still ask, unless every target is in a temporary or work directory (`/tmp`, the session's working directories, `~/ag-work`, `~/wt`, Claude Code's worktrees) or the "Auto-allow deleting and overwriting too" setting is on. Version 0.2.33 keeps agy assistant writes working when ACP `additionalDirectories` add the current conversation's Persona supervision directory to `workspacePaths`; unrelated project workspaces and other sessions' directories still ask. Version 0.2.32 covers shell-parser confirmations, including zsh `${(P)k}` probes and statically resolved indirect scratch targets. Known root/home deletion targets, dynamic executables and evaluated zsh expansions still ask even with that setting on. Force pushes, permission changes, every other tool, and your own ask and deny rules always ask. Each allow is logged with the command cut and secrets masked. A separate setting, off by default, also allows `Write`/`write_file` and `Edit`/`edit_file` from Persona's main and supervisor conversations into listed directories (`~/.jarvis/assistant`, `~/.persona/assistant`).
