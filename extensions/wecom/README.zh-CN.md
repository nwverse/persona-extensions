# 企业微信

[English](README.md) · [扩展开发](../../docs/development.md) · [安装](../../docs/installation.md)

在企业微信里和 Persona 对话。这个扩展驱动**你自己组织的企业微信智能机器人**（API 模式），提供 id 为 `wecom` 的连接器和渠道。它通过官方 Go 进程扩展 SDK 独立于 `personad` 运行，使用机器人的长连接：由 hub 主动连接 `wss://openws.work.weixin.qq.com`，不需要公网地址或回调地址。

| 扩展点 | 贡献 | 行为 |
| --- | --- | --- |
| `connectors` | `wecom` | 登录（机器人的 BotID 和长连接 Secret，然后发配对码）和状态。不会往收件箱或知识库写任何内容。 |
| `channel` | `wecom` | 和机器人单聊：接收文字、图文混排、图片、文件、语音（企业微信的转写）和引用；以 Markdown 发回回答、提示、提问和推送。 |

## 机器人能看到什么、看不到什么

智能机器人只能收到别人发给它的消息：和它的单聊，以及群里 @ 它的消息。它读不到你自己的聊天，所以这个扩展是和 Persona 对话的入口（渠道），不是同步你会话的数据源。和 Persona 的所有渠道一样，群消息会被忽略。

## 创建机器人

1. 在企业微信管理后台创建一个**智能机器人**，配置模式选 **API 模式**。
2. 在 API 配置里把连接方式选为**使用长连接**，复制 **BotID**，再获取并复制 **Secret**（长连接专用的 Secret，不是回调方式的 Token 或 EncodingAESKey）。
3. 在 Persona 里打开**设置 → 渠道 → 企业微信**（或**设置 → 连接器 → 企业微信**），点**绑定**，填入 BotID 和 Secret。扩展会先订阅一次来校验，通过后显示一个六位数配对码。
4. 10 分钟内在单聊里把配对码发给机器人，发送配对码的人就是主人。

只有主人的消息会交给 Persona。配对之前，机器人会告诉别人怎么配对；配对之后，其他人只会收到一句"这个机器人只为完成配对的人服务"（每人每 10 分钟最多一次）。配对码输错 5 次即作废。重新填写凭证总是需要重新配对。

**一个机器人只能有一个连接。** 企业微信对每个机器人只保留一条长连接，新的订阅会挤掉旧的。如果另一个程序（或另一个 hub）用同一个机器人连接，这个扩展会在状态里说明，并等 30 分钟再接管回来，避免两边互相挤掉。重新绑定可以立即接管。

## 消息

- **收**：文字、图文混排、最多 4 张图片（每张不超过 3 MB）、不超过 50 MB 的文件（企业微信本身限制 20 MB）、语音（取企业微信的转写文本），以及被引用消息的文字。媒体以 5 分钟内有效的地址和每条消息单独的 AES 密钥给出，扩展通过 HTTPS 下载后解密（AES-256-CBC）。文件消息本身不带文件名，文件名取自下载响应的 `Content-Disposition`。视频，以及过大或下载失败的内容，会以文字说明告诉助手。发到哪个对话、`/new`、`/stop`、提问和整轮跟踪都由 hub 的渠道流水线负责（[Persona 渠道文档](https://github.com/nwverse/persona/blob/main/docs/extensions/channels.md)）。
- **发**：Markdown，通过 `aibot_send_msg` 发给主人，每段最多 4000 字（企业微信上限 20480 字节）。企业微信要求主人先给机器人发过消息，每个会话每分钟最多 30 条，而且没有幂等键，所以扩展对 hub 的每个 `ref` 只发送一次。
- **提问和审批**通过文字回答（`asks: text`）。流式回复、卡片和按钮目前还没用上。

## 隐私与网络

BotID、Secret、主人信息（企业微信给机器人的这个人的 id 和配对时间）以及最近处理过的消息 id，都作为连接器的加密密文保存在 hub 的数据库里，不会出现在扩展目录、日志或状态中。退出登录会全部删除并断开连接。不记录消息内容和密钥。

网络授权是 `*.qq.com`（长连接）、`*.myqcloud.com`（腾讯云对象存储，企业微信把消息里的图片和文件存在这里）和 `*.qpic.cn`（另一个腾讯媒体域名）。媒体只从这些域名通过 HTTPS 下载。

## 开发

```sh
go -C extensions/wecom test -race ./...
scripts/package.sh wecom
```

测试跑在一个合成的假长连接上（`internal/wecom/api/apitest`），覆盖：订阅和凭证被拒；心跳；按顺序收消息；发送和发送被拒；被其他连接接管；消息解析（图文混排、语音、引用）；媒体下载和解密（填充、错误密钥、大小限制、未知域名、从下载响应取文件名）；握手请求头的写法；凭证和配对步骤；只转发主人的消息；去重；群消息；退出登录；官方 SDK 的连接器和渠道一致性检查；manifest 与运行时一致；三种语言的文案。

本地测试不等于生产验收。正式使用前，请用真实的智能机器人确认：长连接能建立，配对能完成，并完整跑通一轮测试对话（包括一张图片和一个文件）。
