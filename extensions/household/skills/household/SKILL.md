# 家庭管家（household 工具）

家里的东西分四块：库存（物品放在哪个位置、还剩多少、什么时候过期）、采购（待买的东西）、家务（谁什么时候做）和餐食（菜谱和排好的几顿饭）。页面和总览卡片读的是同一份记录，你改的东西用户在页面上马上能看到。

工具有九个。`household_status`、`household_list`、`household_meal_suggest` 只读；其余会改数据。

## 工作顺序

1. **先读状态**：`household_status`。它给出需要处理的项目（已过期、已用完、低库存、用量预警、即将过期）、还没买的东西、到期的家务，以及今天和明天的餐食。回答用户之前先看它。
2. **库存看具体的**：要知道某一类或某个名字的东西，用 `household_list`，带 `type` 和可选的 `text`（标题包含的字）。物品会带上估算的数量和状态。
3. **不编造库存**：数量只能来自记录或用户刚告诉你的数字。记录里没有的，就说没有，问用户，不要猜「应该还有半袋」。
4. **记用量用 `household_use`**：用掉了多少，就取走多少。用户说「用完了」时，用掉的量就是现在估算的数量。
5. **补货用 `household_restock`**：它一次为所有需要买的东西建立待买，已经有待买的不会重复建。要买的数量由记录里的 `refill` 决定（没设就是 1）。
6. **采购结束用 `household_purchase`**：买到了（`bought` 为 true，默认）会把买的数量加到物品的估算数量上，并把数量的记录日期设为今天。如果物品的日期已经过了，旧的一批视为扔掉：数量变成这次买的数量，日期清掉（新一批的日期请用户放好后补上）。没有数量的物品（不跟踪数量）只清过期的日期。不买就只关掉这条（`bought` 为 false），库存不变。
7. **家务做完用 `household_chore_done`**：它记下今天完成，并把下一次日期推到「今天加周期」。没有周期的一次性家务完成后不再安排下一次：记录保留（上次日期是今天），只是没有下一次日期了，不要说成已经删除。
8. **排餐食**：`household_meal_suggest` 按手头有的食材推荐菜谱，并说明缺什么、哪些要先用。排一顿饭用 `household_save`，`type` 为 `meal`，带上 `date`（日期）、`slot`（早餐、午餐、晚餐或加餐）和 `recipe`（菜谱 id）。做完或取消由页面完成。
9. **删除必须确认**：`household_remove` 不能撤销，删之前要向用户说清楚删的是什么，得到同意后才调用。

## 工具

每个工具只给一个例子，字段以工具的说明为准。

- `household_status`（只读）：`{}`
- `household_list`（只读）：`{"type": "item", "text": "牛奶"}`，`type` 是 `place`、`item`、`buy`、`chore`、`recipe` 或 `meal` 之一。
- `household_meal_suggest`（只读）：`{"limit": 3}`
- `household_save`：新建或修改一条记录，属性合并写入。`{"type": "item", "title": "纯牛奶", "values": {"qty": 6, "unit": "盒", "min": 2, "expires": "2026-11-20"}}`；改动时带上 `id`。
- `household_use`：`{"id": "<物品 id>", "amount": 1}`
- `household_restock`：`{}`
- `household_purchase`：`{"ids": ["<采购 id>"], "bought": true}`
- `household_chore_done`：`{"id": "<家务 id>"}`
- `household_remove`：`{"id": "<记录 id>"}`，先确认。

## 说明的口径

- 数量是估算的：物品设了日用量的，剩余数量会随天数减少。用户要的是真实数字时，请用户重新数一次，再用 `household_save` 更正。
- 回答用户时用标题（物品名、菜名、家务名），不要把 id 当作用户关心的内容；id 只用来继续操作。
- 「即将过期」的东西是提醒用户先用掉，不是要买；只有「已过期」「已用完」「低库存」「用量预警」才进入补货。
- 汇总（需要处理几项、几项待买、几项家务到期）由工具算出，直接转述，不要自己数。
- 菜谱只列食材，不写用量，所以做完一顿饭不会自动减少库存；要减少就用 `household_use`，并问用户用了多少。
- 示例中的名字和数字只用来示范；用户家里的事实只来自他的记录和他告诉你的话。
